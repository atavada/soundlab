# SoundLab v1.0.0-beta.2 — Per-App Audio Volume Mixing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement per-application audio volume control for macOS 14.2+ using CoreAudio Process Tap (`CATapDescription`), private aggregate devices, real-time buffer gain scaling, and AppKit menu controls.

**Architecture:** A dedicated `ProcessAudio` subsystem in `SoundLabCore` wrapping CoreAudio Process Tap APIs behind `ProcessTapServiceProtocol`. An allocation-free, lock-free real-time IOProc applies gain scaling to tapped process PCM buffers. `ProcessAudioMixer` coordinates running process discovery, app launch/termination lifecycle, and per-bundle-ID volume persistence. `SoundLabUI` introduces `AppVolumeMenuItem` into the menu bar dropdown.

**Tech Stack:** Swift 6.0+ (Strict Concurrency), macOS CoreAudio HAL, `CATapDescription`, `AudioToolbox`, AppKit, ServiceManagement.

**Spec:** [docs/superpowers/specs/2026-09-16-v1.0.0-beta.2-per-app-volume-design.md](docs/superpowers/specs/2026-09-16-v1.0.0-beta.2-per-app-volume-design.md)

## Global Constraints
- Target platform: macOS 11.0+ (base app); `@available(macOS 14.2, *)` for all Process Audio Tap code
- Swift language mode: Swift 6 with strict concurrency checking
- Background agent: `LSUIElement = true`
- Real-time safety: ZERO allocations, ZERO locks, ZERO I/O, ZERO logging in `AudioDeviceIOProc` callback
