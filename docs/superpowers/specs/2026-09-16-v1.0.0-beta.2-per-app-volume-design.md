# SoundLab v1.0.0-beta.2 — Per-App Audio Volume Mixing Design Specification

## 1. System Overview & Goals
SoundLab v1.0.0-beta.2 extends SoundLab from system-wide device switching to granular, per-application volume mixing (similar to SoundSource or Windows Volume Mixer). It uses the native macOS 14.2+ CoreAudio Process Tap API (`CATapDescription`) to intercept, scale, and route audio streams of individual running applications without requiring third-party virtual audio drivers (such as BlackHole or ACE).

### Primary Capabilities
- Enumerate running applications currently emitting or capable of emitting audio streams.
- Create private CoreAudio process taps with `.mutedWhenTapped` behavior to intercept process audio.
- Route intercepted streams through private aggregate devices linked to the active system default output.
- Apply lock-free, allocation-free real-time audio gain scaling (0% to 100%) in CoreAudio `AudioDeviceIOProc` callbacks.
- Persist per-application volume preferences by Bundle Identifier in `UserDefaults`.
- Reconcile active taps immediately when default output hardware changes (e.g. plugging in headphones).
- Automatically release taps and aggregate devices when tapped applications terminate.
- Present a dedicated "APPLICATIONS" section in the menu bar menu with app icons, names, and volume sliders.
- Gracefully fall back on macOS 11.0–14.1 with informational badge, keeping device switching fully functional.

---

## 2. Technical Requirements & OS Floor

- **Minimum Deployment Target**: macOS 11.0+ for base app; `@available(macOS 14.2, *)` for Process Audio Tap subsystem.
- **Frameworks**: `CoreAudio`, `AudioToolbox`, `AppKit`, `Foundation`.
- **TCC Entitlement & Permissions**:
  - `NSAudioCaptureUsageDescription` in `Info.plist` ("SoundLab requires audio recording permission to route and adjust volume for individual applications.").
  - Handled via system audio recording authorization prompt on first tap activation.
- **Real-Time Safety**:
  - Zero heap allocations, zero locks, zero ObjC/Swift runtime messaging, and zero I/O inside IOProc callbacks.
  - Scalar volume values passed via atomic pointers.

## 4. Module Decomposition

### 4.1 Models (`Sources/SoundLabCore/ProcessAudio/Models/`)
- `AudioProcess`:
  ```swift
  public struct AudioProcess: Identifiable, Hashable, Sendable {
      public let pid: pid_t
      public let objectID: AudioObjectID
      public let bundleID: String?
      public let name: String
      public let isMuted: Bool
      public let volume: Float // 0.0 ... 1.0
  }
  ```

### 4.2 Hardware Abstraction (`Sources/SoundLabCore/ProcessAudio/Core/`)
- `ProcessTapServiceProtocol`:
  - `getAudioProcessObjectIDs() throws -> [AudioObjectID]`
  - `getPID(for processObjectID: AudioObjectID) throws -> pid_t`
  - `getProcessObjectID(for pid: pid_t) throws -> AudioObjectID`
  - `createProcessTap(for processObjectID: AudioObjectID, tapUUID: UUID) throws -> AudioObjectID`
  - `destroyProcessTap(_ tapID: AudioObjectID) throws`
  - `createAggregateDevice(description: CFDictionary) throws -> AudioObjectID`
  - `destroyAggregateDevice(_ aggregateID: AudioObjectID) throws`
  - `createIOProc(aggregateID: AudioObjectID, block: @escaping AudioDeviceIOProcBlock) throws -> AudioDeviceIOProcID`
  - `destroyIOProc(aggregateID: AudioObjectID, procID: AudioDeviceIOProcID) throws`
  - `startIO(aggregateID: AudioObjectID, procID: AudioDeviceIOProcID) throws`
  - `stopIO(aggregateID: AudioObjectID, procID: AudioDeviceIOProcID) throws`
- `CoreAudioProcessTapService`: Production CoreAudio C API implementation for macOS 14.2+.
- `MockProcessTapService`: Thread-safe mock implementation for unit tests.

### 4.3 Tap Lifecycle Controller (`Sources/SoundLabCore/ProcessAudio/Controllers/`)
- `ProcessTapController`:
  - Manages single tapped application lifecycle.
  - Owns tap `AudioObjectID`, aggregate `AudioObjectID`, and `AudioDeviceIOProcID`.
  - Maintains `UnsafeMutablePointer<Float>` for lock-free atomic volume communication to IOProc.
  - Exposes `setVolume(_ volume: Float)` which writes to the atomic pointer and triggers volume change callbacks.
  - Handles `recreate(withNewOutputUID: String)` when default audio device switches.
  - Calls teardown in `deinit` to destroy IOProc, stop IO, destroy aggregate device, and destroy process tap.

### 4.4 Mixer Orchestrator (`Sources/SoundLabCore/ProcessAudio/Managers/`)
- `ProcessAudioMixer`:
  - Main coordination manager running on `@MainActor` or thread-safe actor.
  - Injects `SettingsManager`, `DeviceManager`, `ProcessTapServiceProtocol`.
  - Discovers processes emitting audio via `kAudioHardwarePropertyProcessObjectList`.
  - Maps PIDs to running macOS apps via `NSRunningApplication(processIdentifier:)`.
  - Retains dictionary `activeTaps: [pid_t: ProcessTapController]`.
  - Listens to:
    1. `NSWorkspace.didTerminateApplicationNotification`: Tears down tap when application quits.
    2. `DeviceManager` default output device changes: Rebuilds active aggregate devices against new output device UID.
  - Persists volume by bundle ID: `settingsManager.saveAppVolume(volume, forBundleID: bundleID)`.

### 4.5 UI Components (`Sources/SoundLabUI/Menu/AppVolume/`)
- `AppVolumeMenuItem`:
  - Subclass of `NSMenuItem`.
  - Custom `NSView` layout (height: 32pt):
    - App Icon `NSImageView` (16x16 pt).
    - App Name `NSTextField` (truncated to fit).
    - App Volume `NSSlider` (continuous, `0.0 ... 1.0`).
    - Percentage label `NSTextField` ("100%").
    - Optional mute button `NSButton`.
- `MenuBuilder` update:
  - Adds collapsible or clean "APPLICATIONS" section below Output Volume slider.
  - Generates `AppVolumeMenuItem` for each active audio process.
  - If macOS < 14.2: Displays single informational item: "Per-app volume requires macOS 14.2+".

## 5. Failure Modes & Edge Case Handling

1. **Physical Device Clock Stalls / AirPods HFP Rate Shifts**:
   - Aggregate device includes physical output device as subdevice with `kAudioSubTapDriftCompensationKey: true`.
   - When AirPods shift to 24kHz mono or sample rate changes, `DeviceManager` change callback triggers `ProcessAudioMixer.refreshOutputRouting()`.
2. **App Termination While Tapped**:
   - `NSWorkspace.didTerminateApplicationNotification` fires -> `ProcessAudioMixer.removeTap(for: terminatedPID)`.
   - Resources freed immediately to avoid orphan CoreAudio objects.
3. **Denied TCC Permissions**:
   - When `AudioHardwareCreateProcessTap` returns `kAudioHardwareIllegalOperationError`, show non-blocking dialog instructing user to grant System Audio Recording permission in System Settings -> Privacy & Security -> Screen & System Audio Recording.
4. **Real-Time Safety Invariant**:
   - IOProc audio processing function must pass static code verification: no reference types, no memory allocations, only unsafe buffer arithmetic.

## 6. Verification & Testing Strategy

1. **Unit Testing (`SoundLabCoreTests`)**:
   - `MockProcessTapService` simulates process audio enumeration, tap creation, aggregate creation, and IOProc callback execution.
   - Tests verify:
     - Volume gain scalar multiplication on Float32 PCM sample buffers.
     - Tap teardown on process termination.
     - Output device change recreates aggregate devices.
     - UserDefaults roundtrip for per-bundle-ID volume memory.
2. **Integration & Manual Testing**:
   - Launch app on macOS 14.2+ host.
   - Play audio in Spotify, YouTube on Chrome, and Music.app.
   - Verify apps appear in menu bar under "APPLICATIONS".
   - Adjust volume sliders: verify audio volume of target app attenuates independently without affecting other apps or master system volume.
